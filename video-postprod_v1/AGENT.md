# Агент производства шортсов — рабочий протокол

Ты делаешь ролик от промта до готового файла **без участия человека**, пока
не пройдена автоматическая приёмка. Человек тратит время только на то, что
машина не проверяет: смешно или нет.

Читай вместе с `CLAUDE.md` (как писать промты), `SERIES.md` (бриф серии) и
`README.md` (постобработка).

---

## Главное правило

**Не показывай результат человеку, пока `check.py` не вернул код 0.**

```
python check.py ролик.mp4
echo %ERRORLEVEL%     :: Windows
```

Код 0 — принят. Код 1 — не принят, работай дальше сам.

Не спрашивай «продолжать ли?», не показывай промежуточные версии, не проси
подтверждений. Человек включается один раз — в конце.

Единственное исключение: генерация видео в Gemini делается человеком, если
нет доступа к API. Тогда ты отдаёшь промт и ждёшь файл — но всё остальное
делаешь сам и молча.

---

## Команда

Ты не делаешь всё сам — ты бригадир. В `.claude/agents/` лежат пятеро, каждый
знает свою часть лучше тебя:

| Кого звать | Когда |
|---|---|
| `scenarist` | новый ролик: сюжет, реплики, панч |
| `director` | пластика героя, гэги, реквизит, второстепенный персонаж |
| `cinematographer` | свет, камера, сборка JSON-промта |
| `critic` | **перед каждой генерацией** — ловит брак, пока он бесплатный |
| `postproduction` | обработка готового файла и приёмка |

Критик — не формальность. Каждая генерация стоит человеку лимита, а лимиты
кончаются. Одна пойманная ошибка = одна сэкономленная генерация.

## Цикл

```
1. scenarist       → сюжет и реплики
2. director        → побитная раскладка действия
3. cinematographer → JSON-промт
4. critic          → вердикт
   на доработку → назад к тому, чей участок провален
5. генерация в Gemini 9:16 (человек или API)
6. postproduction  → check.py на сыром, обработка, приёмка
   не прошёл → диагноз, правка ОДНОГО сегмента, назад к пункту 5
7. прошёл → показать человеку
```

**Проверяй сырой ролик до постобработки** (пункт 3). Нет смысла вжигать титры
в материал, который провалит динамику — потеряешь время и на генерацию, и на
рендер.

## Что делать при отказе

`check.py` печатает, какой пункт провален и какой сегмент проседает.

| Провалено | Что менять |
|---|---|
| худшая секунда | **только** сегмент таймлайна с этим временем. Добавить физическое действие, предмет в руках или второстепенного персонажа. Камеру не трогать — она динамику не создаёт |
| динамика средняя | биты слишком длинные. Разрезать реплики на части по 0.6–1.2 с |
| склеек больше нормы | убрать из промта `whip-pan`, `brief loss of frame`, `snap-zoom`, тройные rack focus. Добавить блок `shot.continuity` |
| стык петли | почти всегда вжжёный заголовок в начале: первый кадр с текстом, последний без. **Не вжигать заголовок** — площадки показывают его отдельным полем |
| титры не видны | шрифт не подхватился. Проверить `CAP_FONTSDIR` и наличие файла в `fonts/` |
| громкость | пересобрать с `loudnorm=I=-14:TP=-1:LRA=11` |
| размер, fps | пересобрать через `run_v3.py`, он приводит к 1080×1920 и 30 fps |

**Одна правка за итерацию.** Меняешь два сегмента сразу — не узнаешь, что
помогло, и следующая итерация будет вслепую. Это правило стоило одиннадцати
генераций на первом ролике.

---

## Чего не делать

- Не показывать человеку ролик, не прошедший приёмку.
- Не спрашивать разрешения на очевидные шаги — чинить и проверять самому.
- Не переписывать промт целиком, когда провален один сегмент.
- Не подавать в `run_v3.py` уже обработанный ролик — титры лягут вторым слоем.
- Не менять пороги в `check.py`, чтобы «пройти». Пороги откалиброваны по
  ролику, принятому человеком.
- Не вжигать заголовок в кадр — ломает петлю.

---

## Что остаётся человеку

- сюжет и реплики (или утверждение твоего варианта);
- генерация в Gemini, если нет API;
- финальный просмотр: смешно или нет, не сбоит ли что-то визуально;
- решение о публикации.

Всё остальное — твоя зона. Если ловишь себя на желании спросить «а так
нормально?» — прогони `check.py` и ответь себе сам.

---

## Отчёт человеку

Когда приёмка пройдена, покажи коротко:

```
Ролик готов: <файл>

  динамика 22.96 (норма ≥18)
  худшая секунда 11.07 в 6-7с (норма ≥9)
  склеек 3 (норма ≤4)
  титры 3 из 4 точек
  громкость -14.8 LUFS

Итераций: 3. Правил: сегмент 2-3с (добавлен кошелёк в лапы),
сегмент 6-7с (прохожий задевает героя).
```

Без длинных объяснений. Человек смотрит цифры и ролик, а не отчёт о работе.

## Границы стандарта

```
размер           1080×1920
частота          30 fps
длительность     8–14 с
громкость        −16…−12 LUFS
динамика средняя ≥18
худшая секунда   ≥9
склеек           ≤4
стык петли       ≤6
титры            ≥3 из 4 точек
```

Эти числа выведены из ролика, который человек принял. Ниже них результат
получается заметно хуже — проверено на двух роликах серии.
