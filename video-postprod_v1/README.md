# Постобработка шортсов: титры, печать, петля, замер

Пакет отработан на одном ролике (панда-стендапер, 10 с, 9:16) за одну сессию.
Всё проверено замерами, не «должно работать», а работает.

Что делает: берёт ролик из Gemini/Veo → распознаёт речь → вжигает пословные
титры, синхронные с речью → ставит печать после нужного слова → зацикливает.

## Запуск

```
python run_v3.py video.mp4
```

Без whisper.cpp — с готовыми таймингами:

```
python run_v3.py video.mp4 --wjson primer_words.json
```

Отдельные шаги:

```
python subs_v8.py video.mp4 words.json out.mp4
python stamp_v1.py "ОДОБРЕНО" stamp.png -12 fonts/NotoSans-Bold.ttf
python loop_v2.py video.mp4 0.80
python measure.py video.mp4
```

## Как устроены титры

Whisper.cpp с `-ml 1 -oj` отдаёт **токены, а не слова**: русское слово
рассыпается на куски. Признак начала нового слова — ведущий пробел в поле
`text`. `subs_v8.py` собирает по нему слова обратно.

**Это главная грабля.** В SRT-выводе пробелов нет вообще, поэтому SRT
использовать нельзя — слова склеятся в «б ам б ук». Только JSON.

Разбивка на титры по четырём правилам сразу: длина строки, длительность,
пауза между словами, конец предложения. Последнее обязательно — без него
конец одной фразы слипается с началом следующей.

Караоке-подсветка через теги `\k`: слово загорается в момент произнесения.

**Проверка обязательна.** Скрипт сравнивает кадры до и после вжигания по
пикселям в зоне титров и падает с ошибкой, если ничего не отрисовалось.
Без этой проверки libass молча отдаёт видео без титров — так было дважды.

## Как устроена печать

Субтитрами прямоугольный оттиск не сделать: рамка и текст живут отдельно и
разъезжаются при повороте. Три попытки провалились. Поэтому печать —
**картинка с прозрачным фоном**, накладывается слоем.

Потёртость: шумовая маска вычитается из альфа-канала, плюс редкие крупные
выкусы по краям. Краска покрывает ~11% площади, как у настоящего оттиска.

Момент печати **вычисляется из тех же данных whisper**, что и титры:
`subs_v8.py` находит слово-триггер (`CAP_STAMP_WORD`), берёт время его
окончания и пишет окно в файл `.stamp` рядом с видео. Вручную секунды не
подставляются никогда.

Печать должна появляться **после** слова, а не поверх него — иначе непонятно,
к чему она относится.

## Как устроена петля

Ролик проигрывается целиком, затем дорисовывается хвост: последний кадр
держится, потом растворяется в первый кадр ролика.

**Ошибка, которую легко повторить:** растворять хвост *внутри* ролика — тогда
съедается концовка, и мелкий текст в финале не успевают прочитать. Только
дорисовывать после.

Вторая тонкость: растворение должно **завершиться до конца хвоста**, с запасом
0.18 с. Иначе последние кадры — ещё смесь, а не чистый первый кадр, и петля не
сойдётся. Проверка стыка это ловит.

Звук не перекодируется по содержанию, только дополняется тишиной.

## Настройки (.env)

```
CAP_FONT=Noto Sans          # имя шрифта (не путь!)
CAP_FONTSDIR=fonts          # папка со шрифтом — на Windows обязательно
CAP_SIZE=68
CAP_MARGIN_V=420            # отступ титров снизу, выше зоны UI TikTok
CAP_MAX_CHARS=26            # символов в строке титра
CAP_MAX_DUR=2.2
CAP_MAX_GAP=0.45            # пауза, разрывающая титр

CAP_STAMP=РОССИЯ            # текст печати
CAP_STAMP_WORD=живу         # после какого слова ставить
CAP_STAMP_ANGLE=-12
CAP_STAMP_DUR=0.85          # сколько держится
CAP_STAMP_Y=1300            # центр по вертикали
CAP_STAMP_W=620             # ширина

CAP_TAIL=0.80               # длина хвоста петли
```

Для нового ролика меняется одно слово: `CAP_STAMP_WORD` и `CAP_STAMP`.

## Замер динамики

```
python measure.py video.mp4
```

Покадровая разница яркости при 12 fps, усреднённая по секундам.

```
0-1с   31.4  ####################################
3-4с   38.8  #############################################
6-7с    9.8  ###########

среднее      22.11   (ориентир 20+)
худшая сек    9.82   (цель: не ниже 10)
склеек           3   [3.0, 4.8, 8.3]

переписывать сегмент 6.0-7.0 — там провал
```

**Худшая секунда важнее средней.** Удержание ломается на провалах, а не на
невысоком среднем. Последняя строка указывает, какой сегмент промта
переписывать — правки делаются адресно, по одной за итерацию.

## Что НЕ решено

- **Шрифты на Windows.** libass не видит системные шрифты; путь к папке
  передаётся через `CAP_FONTSDIR` в фильтр `ass:fontsdir=`. На телефоне это
  работало, на Windows не проверялось — экранирование путей с двоеточием диска
  может потребовать доработки. Это ровно то место, что чинилось в
  `polish.mjs`/`assemble.mjs`.
- **Ошибки распознавания.** Whisper слышит «бомбук» вместо «бамбук». В
  `subs_v8.py` есть словарь `FIX`, пополнять по мере находок.
- **Заголовок в кадре** делался разово через `drawtext`, в конвейер не
  вынесен.
- `stamp_v1.py` берёт шрифт из аргумента; если не передать — путь к DejaVu,
  которого на Windows нет. Передавать `fonts/NotoSans-Bold.ttf`.

## Требования

Python 3, ffmpeg и ffprobe в PATH, numpy, pillow.
Для распознавания — whisper.cpp с моделью `ggml-small.bin` (~466 МБ);
faster-whisper на Android не собирается, на Windows можно и его, но формат
JSON тогда другой и парсер надо будет поправить.
